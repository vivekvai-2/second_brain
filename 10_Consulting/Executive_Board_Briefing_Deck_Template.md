# Executive / Board Briefing Deck — Template

**Type:** Consulting Deliverable Template
**Status:** Active
**Created:** 2026-07-15
**Extracted from:** [[ADP_Keynote_2026]] — the first public deployment of this spine (ADP India engineering leadership, June 2026)
**Use for:** Keynotes, board briefings, CXO-adjacent talks — any single-session engagement where the deliverable is a talk plus a small set of pocket tools the audience keeps.

---

## Purpose

ADP proved the spine works: a 40-minute talk built from PRIS constructs, delivered to a non-academic senior audience, produced two reusable practitioner tools (Green/Amber/Red, Five Ps) with immediate carousel and handbook reuse. This template extracts that architecture so the next briefing can be assembled in under a day instead of built from scratch.

## Deck Architecture

| Section | Slide Budget | Core Argument | Fill-in Prompt |
|---|---|---|---|
| Opening | 2–3 slides | Personal credibility; the audience is already living the transition this talk describes | What is the client's own "story they're already in"? |
| Section 1 — What's Changing | 3–4 slides | The operating environment (technical/regulatory/competitive) is shifting under this specific audience; their stakes are different because of [sector-specific consequence] | What breaks for THIS client if governance fails — payroll, credit decisions, patient safety, market integrity? |
| Section 2 — What Leadership/Governance Now Requires | 3–4 slides | The role is changing from executor to orchestrator/steward; static governance no longer suffices | Which signature construct applies — [[Regulatory_Parallelism]] (multi-regulator burden), [[Governance_Debt]] (compliance drag), or [[Institutional_Coherence]] (fragmented internal roles)? |
| Section 3 — Where the Opportunity Is | 4–5 slides | Reframe from defensive compliance to strategic advantage; name the specific value-capture opportunity for this audience | What does "owning the guardrails" look like in this client's business model? |
| Section 4 — Moving Fast Without Breaking Trust | 3 slides | The practitioner tool block — this is the highest-reuse content in the entire deck | Build a fresh 3-bucket triage tool (Green/Amber/Red pattern) AND a fresh pocket checklist (Five Ps pattern) calibrated to this client's risk categories |
| Section 5 — Sector/Regulatory Specific | 1–2 slides | One memorable one-liner contrasting old regime vs new regime (cf. "GDPR taught rights, DPDP teaches accountability") | What is this sector's equivalent regime-shift one-liner? |
| Close | 3–4 slides | Leadership arc resolution; concrete Monday-morning actions | What are the 3 things the audience does differently starting Monday? |
| Appendix | 3–5 slides | Reference tools: framework-to-client-principles mapping, worked examples, quick-reference card, Q&A prep | Map the deck's constructs onto the client's own named values/principles documents if they have one |

## Reusable Tool-Building Patterns

These are not fixed content — they are generator patterns. Rebuild fresh per engagement using the client's actual risk categories.

### Pattern 1 — Three-Bucket Risk Triage (Green/Amber/Red)
A three-tier classification any audience member can apply to a live decision in under 10 seconds:
- **Green** — low-stakes, use freely (define what qualifies for THIS client)
- **Amber** — medium-stakes, human review *before* action, not after
- **Red** — core/irreversible decisions; human-led, AI or automation is an input, never the author

### Pattern 2 — Pocket Checklist ("Five [X]s")
A five-word alliterative or near-alliterative checklist that survives being remembered without the slide. ADP's version: Purpose, People, Proof, Process, Partner. Build a client-specific variant — the constraint is memorability, not fidelity to the exact five words.

### Pattern 3 — N Governance Questions
A small number (3–5) of plain-language questions anyone in the audience can ask about any system touching their function. ADP's version: Can you explain it? Is it actually true? Can you monitor it once live? Who gets the call when it fails? Map each question back to a construct: explainability → [[Transparency]]; monitoring → [[Governance_Capacity]]; accountability → [[Accountability]].

### Pattern 4 — Regime-Shift One-Liner
A single sentence contrasting the old compliance mental model with the new one, calibrated to the client's regulatory regime. Formula: *"[Old regime] taught you [X]. [New regime] teaches you [Y]."*
